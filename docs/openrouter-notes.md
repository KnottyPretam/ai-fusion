## Reasoning parameter

VERIFIED TODAY (2026-09-07) from the canonical markdown source of the docs page. NOTE: https://openrouter.ai/docs/use-cases/reasoning-tokens 307-redirects to https://openrouter.ai/docs/guides/best-practices/reasoning-tokens — the HTML is JS-rendered, so I fetched the `.md` source (curl -sL https://openrouter.ai/docs/guides/best-practices/reasoning-tokens.md), which is the exact page content.

EXACT request shape, quoted verbatim from the doc section "## Controlling Reasoning Tokens":

{
  "model": "your-model",
  "messages": [],
  "reasoning": {
    // One of the following (not both):
    "effort": "high", // Can be "max", "xhigh", "high", "medium", "low", "minimal" or "none" (OpenAI-style)
    "max_tokens": 2000, // Specific token limit (Anthropic-style)

    // Optional: Default is false. All models support this.
    "exclude": false, // Set to true to exclude reasoning tokens from response

    // Or enable reasoning with the default parameters:
    "enabled": true // Default: inferred from `effort` or `max_tokens`
  }
}

Two ADDITIONAL `reasoning` sub-fields exist beyond that snippet (documented in later sections, OpenAI GPT-5.6+ only):
- "reasoning": { "mode": "standard" | "pro" } — `pro` reroutes to the model's `*-pro` listing. Quote: "`reasoning.mode` is only supported by OpenAI GPT-5.6 and newer, when served by OpenAI or Azure." Independent of effort. Cannot be combined with mid-conversation effort updates (400).
- "reasoning": { "context": "auto" | "all_turns" | "current_turn" } — controls which turns' echoed reasoning the model may use. Quote: "`reasoning.context` is only supported by OpenAI GPT-5.6 and newer."

MID-CONVERSATION EFFORT CHANGE (OpenRouter extension to Chat Completions), verbatim:
{
  "model": "anthropic/claude-fable-5.1",
  "reasoning": { "effort": "high" },
  "messages": [
    { "role": "user", "content": "Plan the migration." },
    { "role": "assistant", "content": "Here's the plan: ..." },
    { "role": "system", "content": "", "configuration_update": { "reasoning": { "effort": "low" } } },
    { "role": "user", "content": "Now rename the config file." }
  ]
}
Rules quoted: no two adjacent updates; must not be the last item; not allowed with `reasoning.mode: "pro"` or `*-pro` models; not allowed on the Batch API. "the first models to accept mid-conversation effort changes were Claude Fable 5.1 and OpenAI GPT-6 Astra."

RESPONSE SHAPE (verbatim from "## Reasoning Details API Shape" / "## Preserving Reasoning"):
- "Reasoning tokens will appear in the `reasoning` field of each message, unless you decide to exclude them." → choices[].message.reasoning (plaintext string)
- choices[].message.reasoning_details (array) non-streaming; choices[].delta.reasoning_details per chunk when streaming.
- "You can also use `reasoning_content` as an alias - it functions identically to `reasoning`."
- reasoning_details object common fields: `id` (string|null), `format` (string), `index` (number, optional). Formats: "unknown", "openai-responses-v1", "azure-openai-responses-v1", "bedrock-openai-responses-v1", "bedrock-xai-responses-v1", "xai-responses-v1", "meta-responses-v1", "anthropic-claude-v1" (default), "google-gemini-v1".
- Three detail types: `reasoning.summary` (field `summary`), `reasoning.encrypted`, `reasoning.text` (fields `text`, `signature`).
- Streaming: "For encrypted reasoning, the content may appear as `[REDACTED]` in streaming responses".
- To preserve across turns pass back message.reasoning (string) OR message.reasoning_details (array). Warning quoted: "the entire sequence of consecutive reasoning blocks must match the outputs generated by the model during the original request; you cannot rearrange or modify the sequence of these blocks."
- Caveat quoted: "Some reasoning models do not return their reasoning tokens ... some (like the OpenAI o-series) do not."
- Billing: "Reasoning tokens are considered output tokens and charged accordingly."

PER-MODEL DISCOVERY (this is the key thing for building a UI — verified present in the live API): each entry in GET /api/v1/models may carry a top-level `reasoning` object:
{ "supported_efforts": [...], "default_effort": "medium", "default_enabled": true, "mandatory": true, "supports_max_tokens": true }
Doc semantics, quoted: supported_efforts "returned in descending effort order (highest first). When `null`, all gateway effort values are accepted. When omitted, the model does not expose effort selection." / default_enabled = "Default on/off state when the user has not set `reasoning.enabled`." / supports_max_tokens = "When present and `true`, show a token budget control and send `reasoning.max_tokens`". / mandatory = "When `true`, hide disable controls and do not send `effort: \"none\"` — the model rejects it." / "Non-reasoning models and dynamic router models (`openrouter/auto`, `openrouter/free`) omit the `reasoning` field."

## Effort values

max, xhigh, high, medium, low, minimal, none

## Provider translation of effort

GATEWAY-LEVEL EFFORT → TOKEN RATIO (verbatim from "### Reasoning Effort Level"; the doc scopes this section to "OpenAI reasoning models (o1 series, o3 series, GPT-5 series) and Grok models"):
- "max" ≈ 95% of max_tokens
- "xhigh" ≈ 95% of max_tokens ("Same allocation as max")
- "high" ≈ 80%
- "medium" ≈ 50%
- "low" ≈ 20%
- "minimal" ≈ 10%
- "none" — "Disables reasoning entirely"
"For models that only support `reasoning.max_tokens`, the effort level will be set based on the percentages above."

ANTHROPIC (verbatim from "#### Reasoning Max Tokens for Anthropic Models"):
- "You can enable reasoning on Anthropic models **only** using the unified `reasoning` parameter with either `effort` or `max_tokens`."
- "When using the `reasoning.max_tokens` parameter, that value is used directly with a minimum of 1024 tokens."
- "The reasoning token allocation is capped at 128,000 tokens maximum and 1024 tokens minimum. The formula for calculating the budget_tokens is: `budget_tokens = max(min(max_tokens * {effort_ratio}, 128000), 1024)`"
- "effort_ratio is 0.95 for max and xhigh effort, 0.8 for high effort, 0.5 for medium effort, 0.2 for low effort, and 0.1 for minimal effort."
- "**Important**: `max_tokens` must be strictly higher than the reasoning budget".
- Thinking display: "For Claude models that support the `thinking.display` field, OpenRouter defaults to **summarized thinking** (`thinking.display: 'summarized'`)". Options: 'summarized' (default) | 'omitted'.
- Effort vocabulary mapping for Claude (from the mid-conversation section): "Claude accepts `low`, `medium`, `high`, `xhigh`, and `max` (`minimal` is sent as `low`, `none` is rejected)."
- CRITICAL for Claude 5.x: per the Opus 5 migration guide — "Like Sonnet 5, Opus 5 supports only adaptive thinking: token budgets (`reasoning.max_tokens` in Chat Completions, `thinking.budget_tokens` in Messages) are ignored." So on Opus 5 / Sonnet 5 you MUST use `effort`, not `max_tokens`.

OPENAI: gateway `effort` maps onto OpenAI's own `reasoning_effort`. Per-model accepted sets differ and are published in each model's `reasoning.supported_efforts` (e.g. gpt-6-astra: [max,xhigh,high,medium,low] and mandatory:true — no "none"; gpt-5.6-* : [max,xhigh,high,medium,low,none]; legacy gpt-5/mini/nano: [high,medium,low,minimal]). "an update with an effort the model does not support is rejected with a 400."

xAI / GROK: covered by the same OpenAI-style effort→ratio table above ("and Grok models"). There is NO separate xAI provider section in the doc. Live API: grok-4.6 supported_efforts [xhigh,high,medium,low] with mandatory:true (cannot disable); grok-4.5 [high,medium,low] mandatory:true; grok-4.3 [high,medium,low,none] mandatory:false, default_effort "low".

GOOGLE (for contrast, since it's the only other documented mapping): Gemini 3 maps reasoning.effort to `thinkingLevel`.

WHAT "OFF" MEANS — four distinct things, do not conflate:
1. OMIT `reasoning` entirely = provider/model default. That default is NOT "off" on modern models: Opus 5, Sonnet 5, gpt-5.6-*, gpt-6-astra, grok-4.6 all publish `default_enabled: true`. Opus 5 migration guide: "requests that don't configure reasoning run with adaptive thinking **enabled**" — "a first for Opus-family models".
2. `"enabled": false` = genuinely disable reasoning. This is the portable way to turn it off. Anthropic caveat (Opus 5 guide): disabling is "allowed at `high` or lower; `xhigh` and `max` require reasoning to stay on" — `{"enabled": false, "effort": "xhigh"}` returns a 400 from Anthropic.
3. `"effort": "none"` = "Disables reasoning entirely", but only on models whose `supported_efforts` includes "none" AND `mandatory: false`. Doc: "When `true` [mandatory], hide disable controls and do not send `effort: \"none\"` — the model rejects it." Claude rejects `none` outright.
4. `"exclude": true` = NOT off. "The model will still use reasoning, but it won't be returned in the response" — you still pay for the reasoning tokens. This is the one to use for a council app that wants clean JSON out without the CoT.
Also: `"enabled": true` alone = "Enables reasoning at the 'medium' effort level with no exclusions."

LEGACY (verbatim from "## Legacy Parameters"): "`include_reasoning: true` - Equivalent to `reasoning: {}`" and "`include_reasoning: false` - Equivalent to `reasoning: { exclude: true }`". "we recommend using the new unified `reasoning` parameter". The API-reference page describes `include_reasoning` as "Deprecated alias for reasoning.exclude". Note `include_reasoning: false` does NOT disable reasoning, it only hides it.

## Web search

VERIFIED against https://openrouter.ai/docs/features/web-search (canonical path now /docs/guides/features/plugins/web-search; raw markdown at .../web-search.md).

THREE MECHANISMS, all current:

(1) `:online` model-slug suffix — the shortcut.
```json
{
  "model": "openai/gpt-5.2:online"
}
```
Stackable with `:free`: `{"model": "openai/gpt-oss-20b:free:online"}`. Doc note: "Using web search will incur extra costs, even with free models."
Doc says `:online` "is a shortcut for using the `web` plugin, and is exactly equivalent to":
```json
{
  "model": "openrouter/auto",
  "plugins": [{ "id": "web" }]
}
```

(2) The `web` PLUGIN (full config, quoted verbatim including the inline comments):
```json
{
  "model": "openai/gpt-5.2:online",
  "plugins": [
    {
      "id": "web",
      "engine": "parallel", // Optional: "native", "exa", "firecrawl", "parallel", "perplexity", or undefined
      "mode": "turbo", // Optional; accepted values depend on the selected engine
      "max_results": 1, // Defaults to 5
      "search_prompt": "Some relevant web results:", // See default below
      "include_domains": ["example.com", "*.substack.com"], // Optional
      "exclude_domains": ["reddit.com"] // Optional
    }
  ]
}
```
Default search_prompt (verbatim):
```
A web search was conducted on `date`. Incorporate the following web search results into your response.

IMPORTANT: Cite them using markdown links named using the domain of the source.
Example: [nytimes.com](https://nytimes.com/some-page).
```

(3) PROVIDER-NATIVE search via top-level `web_search_options`:
```json
{
  "model": "openai/gpt-4.1",
  "messages": [
    { "role": "user", "content": "What are the latest developments in quantum computing?" }
  ],
  "web_search_options": { "search_context_size": "high" }
}
```
`search_context_size` ∈ low | medium | high.

(3b) NEW/ADDITIONAL — a BETA server tool the plugin page now actively recommends over the plugin: `openrouter:web_search`, passed in `tools`. Doc: "Server tools are currently in beta. The API and behavior may change." Shape:
```json
{
  "tools": [{ "type": "openrouter:web_search" }]
}
```
with optional params:
```json
{
  "type": "openrouter:web_search",
  "parameters": {
    "engine": "exa",
    "max_results": 5,
    "max_total_results": 20,
    "search_context_size": "medium",
    "allowed_domains": ["example.com"],
    "excluded_domains": ["reddit.com"]
  }
}
```
Extra server-tool params: `mode`, `max_uses`, `max_characters` (1–100,000), `user_location` ({type:"approximate", city, region, country, timezone}). `max_results` default 5, range 1–25 (1–20 Perplexity). Server-tool budget: top-level `max_tool_calls` (sibling of `messages`/`tools`), "defaults to 30 steps, which is also the maximum"; `stop_server_tools_when` overrides it.

ENGINE selection (`engine`): `native` | `exa` | `firecrawl` | `parallel` | `perplexity` | undefined. Undefined => "Native search is used by default for OpenAI, Anthropic, Google, Perplexity, and SpaceXAI models that support it"; Exa otherwise. Explicit `"engine": "native"` always attempts native "even if the model doesn't support it (which may result in an error)."

```

THE FINAL USAGE CHUNK (Chat Completions) — verbatim heading and body: "On the Chat Completions endpoint (`/api/v1/chat/completions`), every stream ends with an extra chunk that carries the `usage` object for the request, sent just before the `[DONE]` message. ```
data: {"id":"gen-abc123",...,"choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":"stop","native_finish_reason":"stop"}]}
data: {"id":"gen-abc123",...,"choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":"stop","native_finish_reason":"stop"}],"usage":{...}}
data: [DONE]
```
"This means the terminal `finish_reason` appears twice: once on the last content-bearing chunk and again on the usage chunk. Clients that validate streams should treat the usage chunk as an accounting frame rather than a second terminal event."
Other endpoints differ: Responses API reports usage in the `response.completed` event; Messages API in `message_delta` before `message_stop`.

GENERATION ID HEADER: "The generation ID is returned in the `X-Generation-Id` response header for all endpoints (chat completions, completions, responses, and messages)".

- `X-OpenRouter-Experimental-Metadata: enabled` (also referenced as `X-OpenRouter-Metadata`) — opts into the `openrouter_metadata` routing-context object on responses and on 403 guardrail errors. See uncertainties: the docs use both spellings.
- Response headers you should read: `X-Generation-Id` (all inference endpoints), and on 429/503 error responses `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`, `Retry-After`.

The OpenRouter TypeScript SDK (`@openrouter/sdk`) takes these as constructor options `httpReferer` and `appTitle` instead of raw headers. With the OpenAI Python SDK, pass them via `extra_headers={...}`.

## Uncertainties (models)

- NOTHING WAS EXECUTED AGAINST THE CHAT API. I had no API key and this was a strict read-only recon task, so no request shape below was confirmed by an actual 200/400 from OpenRouter. Everything is from published docs + the public models endpoint.

The raw HTML of the docs site is JS-rendered — stripping tags yields no body text — so I used the site's `.md` source endpoint. That is the same content the rendered page shows, but it is worth knowing I did not read pixels.
- There is NO xAI/Grok-specific provider section in the reasoning docs. Grok is only covered by the blanket 'OpenAI reasoning models ... and Grok models' scope on the effort->percentage table. Whether Grok actually allocates ~80% of max_tokens at effort:'high', or whether xAI just receives a passthrough reasoning_effort string, is not stated anywhere I could find. Treat the Grok ratio mapping as unverified.
- 'minimal' is a valid gateway effort value but is NOT in the supported_efforts list of ANY current Anthropic, x-ai, gpt-5.6 or gpt-6 model — only the legacy openai/gpt-5, gpt-5-mini, gpt-5-nano list it.
